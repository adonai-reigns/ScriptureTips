# @scripturetips/db

The PostgreSQL schema (Drizzle), its migrations, the connection, and databases for integration tests. So far: scripture text (domain-model §2): `translation`, `translation_book`, `verse_text`, `translator_note` (§2.6) and `translation_import`. Loaded by `tools/scripture-import`. Accounts (domain-model §5) in the shape Better Auth expects: `user` (with `handle`, `locale`, `trust_level`), `session`, `auth_account` (Better Auth's "account", renamed so it isn't mistaken for the user's account) and `verification` (sign-in codes, hashed). Compilations (domain-model §2.3): `compilation` (owner, slug unique per owner, title, abbreviation, base translation, scheme) and `compilation_rule` (kind, canonical `scope` range, the reference as entered, source translation), deleted with their compilation; `compilation_verse` (single-verse choices, edits with the source snapshot, and the user's own or pasted wording) , `compilation_note` (a source note reworded or removed, or the user's own note, on a compilation verse) and `compilation_verse_revision` (every save and reset, with the notes). Authorship evidence (§2.3.1): `authorship_journal` (one per writing session, with its start text, current text and chain head), `composition_event` (hash-chained bursts of writing, with paste origin), `study_trail`, `similarity_report` and `authorship_declaration`. The index also re-exports Drizzle's query helpers (`eq`, `and`, `sql` …), so every package uses this one copy of Drizzle and its types.

- **Schema changes go through migrations.** Edit `src/schema.ts`, then `./toolbox pnpm --filter @scripturetips/db generate <name>`, and commit the SQL in `migrations/`. Never edit a migration that has been applied; write a new one.
- **Keys are UUIDv7** (domain-model §1.1), made by PostgreSQL 18's `uuidv7()`.
- **Passages** are stored as canonical ordinal ranges (`int4range`, inclusive, from @scripturetips/passage) with a GiST index, so "what overlaps this passage" is one query.
- **Development database:** `./dev up` (on the host), then `./toolbox pnpm --filter @scripturetips/db migrate`. The toolbox reaches it through `DATABASE_URL` (compose.yaml).
- **Integration tests** (testing.md §10) run on the `postgres-test` service, which starts with the toolbox and keeps its data in memory. Add `@scripturetips/db/test-support/global-setup` to a package's `vitest.config.ts`: each run migrates its own template database, and `testDatabase()` gives each test file a fresh clone.

Run the tests: `./toolbox pnpm --filter @scripturetips/db test`
